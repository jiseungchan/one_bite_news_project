## 한 줄 요약
> 코드를 '작성'하던 AI가 이제 소프트웨어를 '만드는' 에이전트로 진화하고 있다 — 그 차이가 개발 직군 전반을 재편하고 있다.

## 리드 — 왜 지금 이게 중요한가?

개발자들이 AI를 도구로 쓰던 시대가 끝나가고 있다. 에이전트 AI(Agentic AI — 목표를 받으면 스스로 계획을 세우고 여러 단계를 자율적으로 실행하는 AI 시스템)는 이제 코드 한 줄을 제안하는 수준이 아니라, "이 기능을 구현해줘"라는 지시 하나로 설계부터 테스트·배포까지 전 과정을 처리한다. MIT Technology Review는 이 변화가 단순한 생산성 향상이 아니라 소프트웨어 개발 직군의 역할 자체를 재정의하고 있다고 분석한다.

## 배경 — 기존에는 어땠나?

지난 2~3년간 AI 코딩 도구는 GitHub Copilot(개발자가 코드를 입력할 때 다음 줄을 자동 완성해주는 AI 보조 도구)으로 대표되는 자동완성 모델이 주류였다. 개발자가 함수 이름을 입력하면 AI가 구현부를 채워주는 식이다. 이 방식은 생산성을 높였지만, 개발자가 여전히 매 단계에서 판단하고 승인해야 했다.

문제는 현대 소프트웨어 개발이 단순히 '코드 입력'이 아니라는 점이다. 요구사항 분석 → 아키텍처 설계 → 코드 작성 → 테스트 → 버그 수정 → 배포까지 수십 개의 결정이 연결된 복잡한 프로세스다. 기존 AI 도구는 이 흐름의 일부만 담당했다.

## 핵심 — 무엇이 다른가?

에이전트 AI가 다른 이유는 **멀티스텝 자율성**에 있다. 사용자가 "사용자 로그인 기능을 만들어줘"라고 입력하면, 에이전트는 다음 과정을 스스로 판단해 실행한다:

1. 요구사항 분해 — 인증 방식, 데이터베이스 스키마, API 설계 결정
2. 코드 생성 — 프론트엔드·백엔드 코드 동시 작성
3. 테스트 작성 — 유닛 테스트(개별 기능을 독립적으로 검증하는 자동화 테스트)와 통합 테스트 자동 생성
4. 오류 수정 — 테스트 실패 시 스스로 원인을 분석하고 코드 수정
5. 문서화 — API 문서를 자동 생성

| 항목 | 기존 AI 코딩 도구 | 에이전트 AI |
|------|----------------|----------|
| 개입 단위 | 코드 줄·함수 단위 | 기능·프로젝트 단위 |
| 개발자 역할 | 직접 코딩 + AI 검토 | 요구사항 정의 + AI 결과 검토 |
| 컨텍스트 보유 | 현재 파일 수준 | 전체 코드베이스 수준 |
| 오류 처리 | 개발자가 수동 수정 | 에이전트 자율 재시도 |

이 변화는 마치 '계산기'와 '자동화 회계 시스템'의 차이와 비슷하다. 계산기는 사람이 모든 연산을 지시해야 하지만, 자동화 시스템은 목표(결산서 작성)를 주면 과정을 스스로 처리한다.

## 시장 영향 — 어디에 쓰이나?

- 스타트업 개발 속도: 에이전트 AI를 도입한 팀에서 MVP(최소 기능 제품) 개발 기간이 기존 대비 단축되는 사례들이 보고되고 있다
- 직무 변화: 주니어 개발자의 반복 코딩 업무가 줄고, 아키텍처 설계와 에이전트 감독 역량이 중요해지고 있다
- 도입 기업: Microsoft(GitHub Copilot 에이전트 모드), Google(Project IDX), Cursor, Devin 등이 에이전트 개발 도구 시장을 확장 중이다
- 영향 직군: 풀스택 개발자, QA 엔지니어, DevOps — 특히 반복 테스트 작업 비중이 높은 포지션

## 병규의 한 줄

이번 변화에서 흥미로운 건 AI가 '도구'에서 '팀원'으로 포지셔닝되고 있다는 점이다. 지금껏 개발 도구는 사람이 지시하면 실행하는 수동적 존재였는데, 에이전트는 목표만 주면 과정을 스스로 채운다 — 이는 '코딩 능력'보다 '요구사항을 명확히 정의하는 능력'이 앞으로의 핵심 개발 역량이 된다는 뜻이다.
