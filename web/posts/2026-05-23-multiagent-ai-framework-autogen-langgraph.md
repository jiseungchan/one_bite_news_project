## 한 줄 요약
> 혼자 잘하는 AI 하나보다 역할을 나눈 AI 여럿이 복잡한 일을 더 잘 해낸다 — 멀티에이전트 구조가 실제 기업 현장에 뿌리내리고 있다.

## 리드 — 왜 지금 이게 중요한가?

AI 에이전트 하나에 모든 걸 맡기던 시대가 빠르게 지나가고 있다. 2026년 상반기 기준으로 국내 IT 서비스·금융·제조 기업 30여 곳이 AutoGen(마이크로소프트가 개발한 멀티에이전트 조율 프레임워크)이나 LangGraph(LangChain이 만든 에이전트 워크플로우 설계 도구)를 내부 업무 자동화에 도입했다는 조사 결과가 5월 22일 인공지능신문을 통해 공개됐다. 핵심 수치는 하나다. 단일 LLM(Large Language Model — 대형 언어 모델) 호출 방식 대비 복잡 태스크 완료율이 평균 47% 향상됐다.

## 배경 — 기존에는 어땠나?

GPT-4, Claude 3 같은 대형 모델이 등장했을 때 기업들이 가장 먼저 시도한 방식은 단순했다. 모델에 긴 프롬프트를 넣고 원하는 결과를 바로 받는 것이었다. 이 방식은 정형화된 단순 작업에는 효과적이었지만, 현실 업무에는 한계가 있었다.

예를 들어 "경쟁사 3곳의 최신 보도자료를 수집하고, 각각의 주요 제품 변경 사항을 정리한 뒤, 내부 보고서 형식으로 작성해줘" 같은 요청은 단일 AI 호출로는 처리가 어렵다. 웹 검색, 문서 파싱, 요약, 형식 변환이라는 서로 다른 능력이 순서에 맞게 연결돼야 하기 때문이다. 실제 테스트에서 이런 멀티스텝 태스크의 단일 모델 완료율은 20~30% 수준에 머물렀다.

## 핵심 — 무엇이 다른가?

멀티에이전트 프레임워크의 발상은 인간의 팀 운영 방식과 닮았다. 역할을 분리하고, 각자가 잘하는 것만 맡기며, 결과를 취합하는 조율자(오케스트레이터)를 둔다.

**AutoGen의 경우:**
- '사용자 프록시 에이전트'가 목표를 받아 하위 에이전트들에게 작업 지시
- 각 에이전트는 코드 실행, 웹 검색, 문서 작성 등 역할이 고정
- 에이전트 간 대화 히스토리를 공유해 앞 단계 결과를 뒷 단계에 전달

**LangGraph의 경우:**
- 워크플로우를 방향성 그래프(작업 흐름을 노드와 화살표로 시각화한 구조)로 정의
- 조건 분기(에러가 나면 다른 경로 실행 등)와 반복 루프 지원
- 체크포인트 기능으로 중간 상태를 저장해 장시간 작업도 안정적으로 처리

| 항목 | 단일 LLM 호출 | 멀티에이전트 |
|------|--------------|------------|
| 복잡 태스크 | 완료율 20~30% | 완료율 60~70% |
| 에러 처리 | 처음부터 재시작 | 실패 단계만 재실행 |
| 추적·감사 | 블랙박스 | 단계별 로그 |
| 비용 | 1회 호출 비용 낮음 | 에이전트 수만큼 비용 증가 |

## 시장 영향 — 어디에 쓰이나?

국내 도입 사례를 보면 활용 분야가 빠르게 넓어지고 있다.

- **금융권**: 하나은행·신한카드 등이 여신 심사 보조 자동화에 LangGraph 기반 멀티에이전트를 시범 적용 중
- **제조·SI**: 삼성SDS·LG CNS가 내부 IT 운영 티켓 분류·처리 자동화에 AutoGen 활용
- **공공**: 지방자치단체 민원 처리 프로세스 자동화 파일럿이 경기도·인천시에서 진행 중

업계 컨설팅 기관 가트너(Gartner)는 2027년까지 대기업의 25%가 멀티에이전트 구조를 핵심 업무 프로세스에 적용할 것으로 전망했다.

## 병규의 한 줄

흥미로운 건 멀티에이전트가 AI를 '더 강하게' 만드는 게 아니라 '더 신뢰할 수 있게' 만든다는 점이다. 단계별 감사가 가능해지면, 기업이 AI를 실제 의사결정에 쓸 수 있는 문턱이 낮아진다.
