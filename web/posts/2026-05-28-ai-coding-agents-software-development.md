## 리드

지난 6개월 사이 실리콘밸리 스타트업에서 조용한 실험이 진행됐다. 엔지니어 1명이 AI 코딩 에이전트를 붙여두고 주 40시간짜리 기능 개발을 3일 안에 끝내기 시작한 것이다. Anthropic이 공개한 내부 데이터에 따르면, Claude Code를 사용하는 팀의 풀 리퀘스트(PR — 코드 변경 요청) 병합 속도가 기존 대비 평균 2.8배 빨라졌다.

## 배경 — 기존에는 어땠나?

AI 코딩 도구의 역사는 짧지 않다. GitHub Copilot이 처음 등장한 2021년부터, AI는 개발자 옆에서 코드 한 줄씩을 제안하는 자동완성 도구로 자리잡았다. 유용했지만 본질적으로 소극적이었다. 개발자가 커서를 멈추면 제안이 뜨고, 개발자가 탭을 누르면 적용됐다. AI는 여전히 조수 역할이었다.

문제는 소프트웨어 프로젝트의 복잡성이 여기서 멈추지 않는다는 것이다. 코드 한 줄을 고치면 다른 파일 세 곳이 연쇄적으로 영향을 받고, 테스트가 실패하고, 문서를 업데이트해야 한다. 이 연쇄 작업을 관리하는 것은 여전히 온전히 사람의 몫이었고, 그 맥락을 AI가 이해하지 못했다.

2025년 말까지만 해도 AI 코딩 도구 사용률은 높았지만 "실제로 도움이 되나"라는 질문에는 팀마다 답이 달랐다. 자동완성은 쓰지만 복잡한 리팩토링(기존 코드 구조를 개선하는 작업)에는 못 믿겠다는 반응이 많았다.

## 핵심 — 무엇이 달라졌나?

올해 들어 달라진 건 에이전트의 '자율성'이다. Claude Code나 OpenAI Codex Agent 같은 최신 AI 코딩 에이전트는 단일 파일을 편집하는 게 아니라, 전체 저장소(repository)를 탐색하면서 문제를 진단하고 여러 파일을 동시에 수정한 뒤 테스트까지 돌린다.

동작 방식을 단계로 보면 이렇다.

1. 개발자가 자연어로 목표를 설명한다. ("결제 모듈에서 할인 쿠폰이 중복 적용되는 버그를 고쳐줘")
2. 에이전트가 코드베이스 전체를 읽고 관련 파일을 추적한다.
3. 수정 계획을 세우고, 병규에게 승인을 요청하거나 자동으로 실행한다.
4. 변경 후 테스트를 실행하고 실패한 케이스를 스스로 수정한다.
5. PR을 생성하고 변경 내용을 요약 정리한다.

| 항목 | 기존 자동완성 (Copilot 초기) | 최신 AI 코딩 에이전트 |
|------|----------------------|------------------|
| 작업 범위 | 단일 파일, 한 줄 | 전체 저장소 다중 파일 |
| 개발자 역할 | 모든 판단 직접 수행 | 목표 설정 + 결과 검토 |
| 테스트 연동 | 없음 | 자동 실행 후 피드백 |
| 컨텍스트 유지 | 현재 창 내용만 | 프로젝트 전체 구조 이해 |

MIT Tech Review가 인터뷰한 12개 개발팀 중 8개 팀이 "AI 에이전트 도입 후 기능 개발 사이클이 30~50% 단축됐다"고 답했다. 다만 코드 리뷰(작성된 코드를 검토하는 과정)에 오히려 더 많은 시간을 쓰게 됐다는 반응도 함께 나왔다.

## 시장 영향 — 어디에 쓰이나?

- Anthropic Claude Code: 엔터프라이즈 구독 기준 월 100달러. 5월 기준 Fortune 500 기업 중 34%가 파일럿 테스트 중
- OpenAI Codex Agent: ChatGPT Enterprise 내 통합. 주로 내부 도구 자동화에 활용
- Cursor, Windsurf 등 전문 IDE(통합 개발 환경): 스타트업 개발팀 사이에서 채택률이 6개월 새 3배 증가

가장 눈에 띄는 변화는 '주니어 개발자'의 역할 재정의다. 단순 반복 코딩 업무가 에이전트로 대체되면서, 신입 개발자에게 요구되는 역량이 "빠른 코딩"에서 "AI 출력을 검토하고 요구사항을 정교하게 지시하는 능력"으로 이동하고 있다는 분석이 나온다.

## 병규의 한 줄

> 이번에 흥미로운 건 속도 수치보다, '누가 코드를 소유하는가'라는 질문이다. AI가 코드를 쓰고 사람이 검토하는 구조가 정착되면, 소프트웨어 팀의 책임 구조 자체가 다시 설계돼야 한다. 도구가 바뀌는 게 아니라 조직이 바뀌는 것이다.
