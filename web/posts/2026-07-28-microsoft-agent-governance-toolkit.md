## 한 줄 요약
> 마이크로소프트의 Agent Governance Toolkit은 AI 에이전트가 허용되지 않은 행동을 취하는 것을 "구조적으로 불가능"하게 만든다 — 프롬프트에 의존하지 않고, 결정론적 코드가 판단한다.

## 리드 — 왜 지금 이게 중요한가?

AI 에이전트를 실무에 투입하면 반드시 맞닥뜨리는 질문이 있다. "이 에이전트가 해서는 안 될 일을 할 가능성을 어떻게 막을 것인가?" 마이크로소프트가 오픈소스로 공개한 Agent Governance Toolkit(AGT)은 이 질문에 프롬프트 수준이 아닌 애플리케이션 레이어에서 답한다. 2026년 4월 첫 릴리스 이후 현재 GitHub 스타 5,200개를 넘긴 이 프로젝트는 에이전트 거버넌스 분야에서 사실상의 표준 레퍼런스로 자리잡고 있다.

## 배경 — 기존에는 어땠나?

지금까지 AI 에이전트의 행동을 제한하는 주요 방법은 두 가지였다. 첫째는 시스템 프롬프트에 "이것은 하지 마세요"라는 규칙을 심어두는 방식, 둘째는 RLHF(인간 피드백 강화학습 — 사람의 평가를 통해 모델을 훈련하는 기법)를 통해 모델 자체의 행동 성향을 조정하는 방식이다. 두 방법 모두 **확률적**이다 — 대부분의 경우엔 작동하지만, 작정하고 조작하면 뚫린다.

AGT 문서가 인용한 연구에 따르면, 프롬프트 인젝션(외부 텍스트를 통해 AI를 조작하는 공격)에 대한 완벽한 방어 방법은 현재 존재하지 않으며, 적응형 공격 조건에서 주요 LLM의 공격 성공률이 100%에 달했다. DB 접근 권한을 가진 에이전트가 교묘하게 조작된 입력 하나로 삭제 쿼리를 실행하는 일이 이론적으로 가능하다는 뜻이다.

멀티에이전트 시스템(여러 AI 에이전트가 협력하는 구조)이 확산되면서 문제는 더 복잡해졌다. "어떤 에이전트가 이 행동을 했는가"를 추적하는 것 자체가 어렵고, 컴플라이언스 감사 때 필요한 의사결정 기록도 남지 않는다.

## 핵심 — 무엇이 다른가?

AGT는 "프롬프트를 믿지 마라"는 철학을 바탕으로 설계됐다. 에이전트가 특정 도구(툴)를 실행하려 할 때, AGT의 정책 엔진이 먼저 가로채서 허용/거부를 결정한다. 이때 판단하는 건 모델이 아니라 **결정론적 코드**다. YAML(사람이 읽기 쉬운 설정 파일 형식)로 "이 에이전트는 DELETE 쿼리 실행 불가"라고 명시하면, 어떤 프롬프트로 속여도 실행이 원천 차단된다.

| 비교 항목 | 기존 방식 (프롬프트/RLHF) | AGT 방식 |
|----------|--------------------------|---------|
| 방어 성격 | 확률적 (대부분 막음) | 결정론적 (구조적 불가) |
| 공격 내성 | 적응형 공격에 취약 | 애플리케이션 레이어 차단 |
| 감사 추적 | 어려움 | 머클 트리 기반 변조 불가 로그 |
| 신원 확인 | 없음 | SPIFFE/DID 기반 에이전트 식별 |

AGT 아키텍처는 4개 레이어로 구성된다. 정책 엔진(행동 허용/거부), 신원 검증(어떤 에이전트인지 추적), 감사 로그(머클 트리 — 블록체인처럼 이전 기록을 참조해 변조를 감지하는 암호학적 자료구조), MCP 보안 게이트웨이(MCP는 AI 에이전트와 외부 도구를 연결하는 표준 프로토콜로, 이 레이어에서 도구 오염·드리프트를 실시간 감지). 각 레이어는 선택적으로 사용 가능하며, 대부분의 팀은 정책 엔진 + 감사 로그 조합부터 시작한다.

## 시장 영향 — 어디에 쓰이나?

- **지원 프레임워크**: OpenAI Agents SDK, LangChain, AutoGen, CrewAI, Semantic Kernel, Claude Code, Google ADK, Azure AI Foundry — 업계 주요 에이전트 프레임워크 전체 포괄
- **규제 대응**: EU AI Act, SOC 2, NIST AI RMF(AI 리스크 관리 프레임워크), OWASP Agentic AI Top 10 전 항목 매핑
- **사용 언어**: Python(전체 기능), TypeScript, .NET, Rust, Go
- **현황**: 공개 프리뷰, v4.1.0(2026년 6월 9일 릴리스), 992개 적합성 테스트(conformance test) 통과

금융·의료처럼 컴플라이언스가 엄격한 산업에서 에이전트를 프로덕션에 배포하려는 팀들에게 거버넌스 기반 레이어로 직접 활용될 수 있다.

## 병규의 한 줄

에이전트 거버넌스의 핵심 전환은 이거다: '모델이 알아서 판단하게 믿는다'에서 '코드가 구조적으로 차단한다'로. 프롬프트 기반 안전장치는 "보통은 막힌다"는 보장만 할 수 있지만, AGT는 "절대 실행되지 않는다"는 보장을 애플리케이션 레이어에서 만든다. AI 안전의 무게중심이 모델에서 인프라로 이동하고 있다.
