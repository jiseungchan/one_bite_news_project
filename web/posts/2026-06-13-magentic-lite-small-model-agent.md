## 한 줄 요약
> 마이크로소프트가 거대한 모델 없이도 제대로 작동하는 AI 에이전트 시스템을 내놨다 — 크기보다 '역할 분리 설계'가 성능을 결정한다는 걸 보여준다.

## 리드 — 왜 지금 이게 중요한가?

마이크로소프트 리서치가 소형 모델 전용으로 최적화한 AI 에이전트 시스템 MagenticLite를 공개했다. 핵심은 14B(140억) 파라미터 수준의 모델로도 브라우저 자동화, 파일 관리, 예약·폼 작성 같은 실제 업무를 처리한다는 것. 기존 Fara-7B 대비 웹 네비게이션 성능이 거의 2배 향상됐고, 웹 에이전트 표준 벤치마크인 OnlineMind2Web(실제 웹사이트에서 사용자 지시를 얼마나 정확히 수행하는지 측정하는 평가 지표)에서 Fara1.5-27B가 90% 이상의 성능을 기록했다.

## 배경 — 기존에는 어땠나?

AI 에이전트(사용자 지시를 받아 스스로 판단·실행하는 자동화 프로그램) 분야에서 지배적인 가정은 '클수록 잘한다'였다. GPT-4o나 Claude 같은 초대형 모델이 있어야 제대로 된 추론과 행동이 가능하다는 것. 소형 모델은 지식 자체가 부족해 에이전트로 쓰기 어렵다는 게 업계의 통념이었다.

문제는 비용과 속도다. 대형 모델 기반 에이전트는 API 비용이 높고, 복잡한 작업일수록 응답 시간이 길어진다. 기업 환경에서 대규모로 배포하기엔 경제성이 맞지 않는 경우가 많았다. '프라이버시'도 걸린다 — 외부 대형 모델 API에 업무 데이터를 보내는 것 자체를 꺼리는 기업들이 적지 않다.

MS Research는 여기서 다른 가정을 세웠다. "에이전트 능력은 지식보다 도구 조율과 실행에 달려 있다"는 것이다.

## 핵심 — 무엇이 다른가?

MagenticLite는 세 구성요소로 이뤄진다:

- **MagenticLite (앱)**: 브라우저와 로컬 파일 시스템을 하나의 워크플로 안에서 통합 제어하는 인터페이스
- **MagenticBrain (14B 파라미터 오케스트레이터)**: 추론, 코딩, 도구 호출, 서브에이전트 위임을 담당하는 '두뇌' 역할
- **Fara1.5 (4B/9B/27B 컴퓨터 사용 모델)**: 실제로 브라우저를 조작하고 화면을 읽는 '손과 눈' 역할

| 구분 | 기존 방식 | MagenticLite 방식 |
|------|-----------|------------------|
| 핵심 가정 | 지식 많은 대형 모델이 전부 처리 | 역할 분리 + 소형 모델 전문화 |
| 모델 규모 | 수백 B 파라미터 | 14B + 9B (오케스트레이터+실행자) |
| 컨텍스트 처리 | 모든 정보 한 번에 입력 | 필요한 정보만 능동적으로 선별 전달 |
| 사용자 개입 | 작업 시작·종료만 | 중요 포인트에서 명시적 승인 요구 |

비유하면, 기존 방식이 '만능 슈퍼 직원 1명이 혼자 다 처리'라면, MagenticLite는 '작업별로 전문화된 소규모 팀이 분담'하는 구조다. 오케스트레이터는 계획만 짜고, 실행은 Fara1.5가 맡는 식이다.

또 하나 눈에 띄는 설계는 사용자 제어권이다. 로그인·결제·권한 요청 같이 돌이킬 수 없는 행동 앞에서 에이전트가 스스로 멈추고 사용자 승인을 기다린다. MS는 이를 '중요 포인트(critical point)'라 부르며, 실제 사용 피드백을 바탕으로 기준을 정교하게 다듬어왔다. 판단 실수로 인한 사고를 막는 안전장치다.

## 시장 영향 — 어디에 쓰이나?

- **OnlineMind2Web 벤치마크**: Fara1.5-27B, 90% 이상 성능 달성
- **웹 네비게이션**: Fara-7B 대비 거의 2배 향상
- 적용 작업: 폼 작성, 예약, 파일 관리, 로그인 등 반복적 사무 자동화
- 기업 내부 배포 시나리오에 유리 — 대형 외부 API 없이 온프레미스(사내 서버) 운용 가능
- 영향 직군: 데이터 입력, 일정 관리, 웹 리서치 보조 등 반복 업무 종사자

## 병규의 한 줄

이번에 흥미로운 건 모델 크기가 아니라 설계 철학이다. '에이전트 성능 = 모델 크기'라는 가정을 깨고, 역할 분리와 컨텍스트 효율화로 소형 모델도 충분히 쓸 수 있다는 걸 보여줬다 — 이게 맞다면 앞으로 에이전트 경쟁의 축이 '얼마나 큰 모델이냐'에서 '얼마나 잘 쪼개서 쓰냐'로 이동한다.
