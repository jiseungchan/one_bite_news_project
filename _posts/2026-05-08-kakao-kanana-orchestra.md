## 한 줄 요약
> 카카오는 AI 하나를 잘 만드는 게 아니라, 여러 AI가 함께 일하는 체계를 설계하는 방향을 택했다.

## 리드 — 왜 지금 이게 중요한가?

카카오가 자체 개발한 멀티에이전트(multi-agent — 여러 AI 에이전트가 역할을 나눠 협업하는 구조) 오케스트레이션 프레임워크 '카나나 오케스트라'를 공개했다. 단일 AI 모델이 모든 것을 처리하는 방식에서 벗어나, 검색·정리·실행·검증을 각각 전담하는 에이전트들이 지휘 체계 아래 협력한다. 카카오가 플랫폼 전략의 무게중심을 모델 성능에서 에이전트 생태계로 이동하고 있다는 신호다.

## 배경 — 기존에는 어땠나?

지금까지 대부분의 AI 서비스는 단일 모델 구조로 운영됐다. 사용자의 요청이 들어오면 하나의 LLM(대규모 언어 모델 — 방대한 텍스트를 학습해 언어를 이해하고 생성하는 AI 모델)이 처음부터 끝까지 혼자 처리하는 방식이다. 이 구조는 단순 질문-답변에는 잘 맞지만, '여러 단계가 연결된 복잡한 작업'에는 취약하다.

예를 들어 "이번 주 회의록 3개를 읽고 핵심 결정 사항을 정리한 뒤 팀 채팅방에 보내줘"라는 요청은 파일 읽기·요약·의사결정 추출·발송이라는 네 가지 작업이 순서대로 연결돼야 한다. 단일 모델로는 각 단계 사이에서 오류가 누적되는 문제가 있었다.

카카오는 카카오톡이라는 메신저 플랫폼에서 이런 복합 작업 요청이 일상적으로 발생한다는 점에서, 이 문제를 직접 해결하는 인프라를 만들기로 했다.

## 핵심 — 무엇이 다른가?

카나나 오케스트라는 오케스트라 지휘자에 비유할 수 있다. 각 악기 주자(개별 에이전트)는 자기 역할만 하고, 지휘자(오케스트레이터)가 전체 흐름을 조율한다. 구조를 단계로 나누면:

1. **작업 분해**: 오케스트레이터가 사용자 요청을 세부 작업으로 쪼갠다
2. **에이전트 배정**: 검색 전담·요약 전담·실행 전담 등 적합한 에이전트를 각 단계에 배정한다
3. **병렬 및 순차 실행**: 독립적인 작업은 동시에, 순서가 있는 작업은 차례로 처리한다
4. **결과 검증**: 각 에이전트의 결과물을 검증 에이전트가 확인한 뒤 다음 단계로 넘긴다

| 구분 | 단일 모델 방식 | 카나나 오케스트라 |
|------|--------------|----------------|
| 작업 처리 | 1개 모델이 전부 담당 | 역할 분리된 다수 에이전트 |
| 오류 처리 | 전체 재시작 | 실패한 에이전트만 재실행 |
| 확장성 | 모델 크기 키우기 | 에이전트 추가로 기능 확장 |
| 비용 | 대형 모델 고정 비용 | 작업 복잡도에 따른 탄력 조정 |

## 시장 영향 — 어디에 쓰이나?

- **카카오톡 연동**: 카카오톡 대화 맥락을 실시간으로 파악하고 일정·검색·쇼핑 등을 자동 처리하는 시나리오에 직접 적용
- **카카오 비즈니스**: 고객 상담 자동화, 주문 처리, CS 티켓 분류 등 기업 고객 서비스에 적용 예정
- **외부 개발자**: API 형태로 제공해 카카오 생태계 파트너들이 에이전트 기반 서비스를 직접 구축할 수 있도록 지원

국내 AI 플랫폼 경쟁에서 카카오는 '모델 성능' 대신 '실생활 연결'을 무기로 삼는 전략을 일관되게 유지하고 있다.

## 병규의 한 줄

카나나 오케스트라에서 흥미로운 건 카카오가 '더 큰 모델'이 아닌 '더 잘 협업하는 에이전트 체계'를 경쟁 전략으로 택했다는 점이다. 모델 파라미터 경쟁보다 플랫폼 인프라 경쟁이 더 현실적일 수 있다는 가정을 이 선택이 담고 있다.
