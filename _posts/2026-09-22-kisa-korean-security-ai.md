클로드나 GPT가 모든 사이버 위협을 막아줄 수 있을까. 한국인터넷진흥원(KISA)의 답은 "한국에서는 그렇지 않다"이다.

## 기존에는 어땠나?

2024~2025년, 기업과 공공기관들은 앞다퉈 외산 LLM(대형 언어 모델, Large Language Model)을 보안 운영에 도입했다. 이상 징후 탐지, 로그 분석, 악성코드 분류 등에서 실제로 효율이 높아졌다. 문제는 그 AI들이 글로벌 위협 패턴을 기준으로 학습됐다는 점이다.

한국의 IT 환경은 꽤 독특하다. 공공기관과 금융권에 필수적인 HWP/HWPX(한글과컴퓨터의 문서 포맷 — 한국 공문서 표준), 물리적으로 인터넷을 분리하는 망분리 시스템, 액티브X 기반 DRM(디지털 저작권 관리, 문서 암호화 기술), 국산 전자금융 보안 모듈 등이 공존하는 생태계다. 미국 중심으로 학습된 모델이 이 환경을 이해하기는 어렵다.

## 무엇이 달라졌나?

KISA 위협대응정책팀 김은성 팀장은 최근 보안 행사에서 핵심을 이렇게 짚었다.

> "망분리·HWP 환경에서 외산 AI는 못 막는다. 클로드나 GPT만 써서는 한국을 겨냥한 사이버 공격에 제대로 대응하기 어렵다. 최소한의 보안 역량을 갖춘 독자 모델이 필요하다."

KISA가 제시한 개발 방향은 이렇다:

1. **정부가 기본 보안 역량을 갖춘 '오픈 웨이트(open weight)' 모델**을 만들어 공개
2. **기업들이 각 산업 특성에 맞게 추가 학습**해 전문 보안 서비스 구축
3. 한국어 사이버 위협 데이터, HWP 취약점 패턴, 망분리 환경 로그를 중심으로 학습

오픈 웨이트 방식은 모델 가중치(weight — AI가 학습한 지식이 숫자로 저장된 파일)를 공개해, 외부 기업·연구자가 자유롭게 가져다 쓸 수 있게 하는 방식이다. GPT처럼 API로만 접근하는 폐쇄형과 달리, 망분리 환경에서도 내부 서버에 직접 설치할 수 있다는 장점이 있다.

## 왜 지금인가?

생성형 AI가 공격 수단이 됐기 때문이다. 허위 스피어피싱(spear phishing — 특정 대상을 노린 맞춤형 피싱) 이메일 생성, 악성코드 자동 변형, 소셜 엔지니어링 스크립트 작성이 AI로 손쉬워지면서 공격 속도가 수비 속도를 압도하기 시작했다.

KISA 관계자는 "AI 해킹 시대에는 취약점을 발견하는 것보다 더 빠른 조치가 관건"이라고 밝혔다. 외산 AI가 한국어 위협 정보를 실시간으로 처리하고 한국 고유 환경 취약점에 대응하는 데 구조적 한계가 있다는 지적이다.

## 시장 영향

아직 구체적인 개발 일정이나 예산 규모는 공개되지 않았다. 그러나 방향은 분명하다. 망분리 기관(공공·금융·국방)에서 외산 AI를 클라우드 API 형태로 쓰기 어려운 만큼, 온프레미스(on-premise — 자체 서버에 직접 설치하는 방식)로 구동 가능한 경량 보안 특화 모델의 수요는 실질적이다.

## 병규의 한 줄

이건 단순한 국산화 구호가 아니다. HWP와 망분리는 한국 공공 IT의 실제 인프라이고, 그 위에서만 작동하는 위협 패턴이 존재한다. 외산 AI가 영어 중심 세계 위협에 최적화됐다면, 한국형 보안 AI는 '한국어로 된 공격'을 이해하는 게 핵심이다. 언어 문제가 아니라 생태계 문제다.
