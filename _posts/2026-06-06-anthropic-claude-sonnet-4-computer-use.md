## 한 줄 요약
> Claude Sonnet 4는 단순히 더 똑똑한 챗봇이 아니라, 화면을 보고 직접 일을 처리하는 AI 에이전트의 완성도를 한 단계 끌어올렸다.

## 리드 — 왜 지금 이게 중요한가?

Anthropic이 Claude Sonnet 4를 공개하면서 AI 에이전트 경쟁이 새로운 국면으로 접어들었다. 이번 모델의 핵심은 'Computer Use(컴퓨터 사용)' 기능의 대폭 향상이다. 이전 버전에서 자주 발생하던 화면 오인식과 잘못된 클릭 문제가 크게 줄었고, 실제 업무 자동화 벤치마크인 OSWorld에서 GPT-4o를 상회하는 성능을 기록했다.

## 배경 — 기존에는 어땠나?

AI가 사람처럼 컴퓨터를 조작한다는 개념은 2024년부터 본격적으로 등장했다. OpenAI의 'Operator', Anthropic의 'Computer Use', 그리고 구글의 'Project Mariner'가 거의 동시에 시장에 나왔다. 아이디어는 단순했다. AI에게 화면을 보여주고 "이 버튼 눌러"라고 지시하면, 사람이 하는 것처럼 마우스를 움직이고 키보드를 입력하게 하는 것이다.

그런데 초기 결과는 기대에 못 미쳤다. 복잡한 UI에서 버튼 위치를 잘못 인식하거나, 웹페이지가 로딩되는 도중에 다음 동작을 실행해버리는 타이밍 문제가 빈번했다. OSWorld(실제 데스크톱 환경에서 작업을 수행하는 AI 벤치마크) 기준으로 초기 모델들의 성공률은 15~20% 수준에 머물렀다. 사람이 같은 작업을 하면 거의 100%인 것과 비교하면, 실용화까지는 거리가 있었다.

이 격차의 핵심 원인은 '좌표 인식의 정밀도'와 '상태 추적 능력'이었다. AI는 화면의 픽셀 좌표를 보고 클릭 위치를 결정하는데, 해상도나 UI 크기가 달라지면 오차가 커졌다. 또한 여러 단계의 작업을 수행하면서 현재 어느 단계에 있는지 맥락을 잃어버리는 문제도 있었다.

## 핵심 — 무엇이 다른가?

Claude Sonnet 4에서 Anthropic이 집중한 부분은 두 가지다.

첫 번째는 '시각적 접지(Visual Grounding)' 능력이다. 화면상의 요소를 절대 좌표가 아닌 의미 단위로 이해하는 방식으로 바꿨다. "저장 버튼"이 어디 있는지를 픽셀로 기억하는 것이 아니라, "저장"이라고 쓰인 버튼을 의미적으로 인식하도록 훈련한 것이다.

두 번째는 '작업 상태 메모리(Task State Memory)'다. 멀티스텝 작업을 처리할 때 이전 단계에서 무엇을 했는지, 현재 목표가 무엇인지를 일관되게 추적하는 내부 메커니즘을 강화했다.

| 항목 | 이전 세대 (Claude 3.5) | Claude Sonnet 4 |
|------|----------------------|-----------------|
| OSWorld 성공률 | 약 22% | 약 38% |
| 멀티스텝 작업 완료율 | 35% | 55% |
| 화면 오인식률 | 높음 | 크게 감소 |
| 작업 맥락 유지 | 3~5단계 | 10단계 이상 |

마치 처음 운전 배우는 사람이 각 조작(핸들, 브레이크, 가속)을 따로따로 생각하다가 점점 통합적으로 처리하게 되는 것처럼, 이번 모델은 화면 보기와 행동 결정을 더 자연스럽게 통합한다는 인상을 준다.

## 시장 영향 — 어디에 쓰이나?

- **기업 업무 자동화**: 반복적인 데이터 입력, 보고서 취합, 소프트웨어 간 데이터 이동 등 RPA(로봇 프로세스 자동화) 시장이 직접 타격을 받는다
- **개발자 도구**: Claude Code와 연동해 테스트 실행·오류 확인·코드 수정을 사람 없이 반복하는 워크플로우 구현 가능
- **소비자 제품**: Notion, Linear, Figma 같은 SaaS 도구 내 자동화 기능으로 탑재될 가능성

Salesforce, Workday 등 엔터프라이즈 소프트웨어 기업들은 이미 Claude API를 통한 에이전트 통합을 검토 중인 것으로 알려졌다.

## 병규의 한 줄

이번에 흥미로운 건 성능 수치보다 접근 방식의 변화다. Anthropic은 "AI가 사람처럼 컴퓨터를 쓴다"는 메타포를 유지하면서도, 내부적으로는 인간의 인지 방식(의미 기반 인식, 상태 추적)을 더 가깝게 모델링하는 쪽으로 방향을 잡고 있다. 좌표를 외우는 AI에서 맥락을 이해하는 AI로 — 이게 진짜 에이전트와 자동화 스크립트의 차이를 만든다.
