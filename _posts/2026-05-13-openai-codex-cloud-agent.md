## 한 줄 요약
> OpenAI Codex는 단순한 코드 자동완성이 아니다 — 개발자 대신 GitHub에 PR을 올리는 첫 번째 '클라우드 소프트웨어 에이전트'다.

## 리드 — 왜 지금 이게 중요한가?

OpenAI가 2026년 5월 소프트웨어 개발 전용 에이전트 Codex를 공개했다. 기존 코파일럿(Copilot — 코드 작성 중 자동완성을 제안하는 AI 보조 도구) 방식과 달리, 이번 Codex는 사용자가 작업을 맡기면 클라우드 샌드박스(격리된 실행 환경) 안에서 독립적으로 코드를 작성하고 테스트한 뒤 결과를 보고한다. 개발자가 화면을 보고 있지 않아도 된다.

## 배경 — 기존에는 어땠나?

지금까지 AI 코딩 도구는 크게 두 가지였다. 첫째는 GitHub Copilot처럼 IDE(통합 개발 환경) 안에서 코드를 한 줄씩 제안하는 방식, 둘째는 ChatGPT에 코드를 붙여넣고 수정 요청을 하는 방식이었다. 두 방식 모두 인간 개발자가 루프 안에 머물면서 매 단계를 직접 확인하고 실행해야 했다.

SWE-bench(소프트웨어 엔지니어링 벤치마크 — 실제 GitHub 이슈를 AI가 자동으로 해결할 수 있는지 측정하는 기준)에서 2024년 기준 최고 성능 모델의 성공률은 약 12%에 불과했다. 즉, 실제 코드베이스에서 실질적인 버그 수정을 자동화하기엔 아직 멀었다는 평가가 지배적이었다.

## 핵심 — 무엇이 다른가?

Codex의 핵심은 '비동기 멀티태스킹'이다. 사용자가 여러 작업을 동시에 맡기면 각각 독립된 샌드박스에서 병렬로 처리되고, 완료되면 알림을 보낸다. 마치 여러 업무를 각 담당자에게 나눠 맡기고 결과만 보고받는 프로젝트 매니저처럼 동작한다.

구체적인 동작 순서는 이렇다:
1. 사용자가 자연어로 작업 설명 ("이 기능에 유닛 테스트를 추가해줘")
2. Codex가 GitHub 저장소(repository)를 클론(clone — 복사)해 격리 환경에서 작업
3. 코드 작성 → 테스트 실행 → 오류 수정을 자동 반복
4. 완료 후 PR(Pull Request — 코드 변경 사항을 원본 저장소에 병합 요청하는 절차) 제출
5. 사람이 검토 후 최종 병합 결정

| 방식 | 인간 개입 시점 | 병렬 처리 | 자율 실행 |
|------|------------|---------|-------|
| GitHub Copilot | 매 줄 | 불가 | 없음 |
| ChatGPT 코드 모드 | 매 요청 | 불가 | 없음 |
| Codex (신규) | 최종 검토만 | 가능 | 전체 |

현재 ChatGPT Pro·Plus·Team 구독자에게 우선 공개됐으며, o3 및 GPT-4.1 기반으로 구동된다.

## 시장 영향 — 어디에 쓰이나?

- **스타트업·소규모 팀**: 백엔드 작업을 에이전트에 위임해 프론트엔드·제품 기획에 집중하는 방식이 현실적인 선택지가 됐다
- **오픈소스 프로젝트 관리**: 이슈가 쌓인 대규모 오픈소스 저장소에서 단순 버그 수정을 자동화하는 용도로 빠르게 도입될 가능성이 높다
- **경쟁 구도**: GitHub Copilot Workspace(마이크로소프트), Devin(Cognition AI), Cursor Agent 등과 직접 경쟁. 소프트웨어 개발 에이전트 시장이 본격적인 전쟁 국면에 들어섰다

## 병규의 한 줄

이번 Codex가 보여주는 것은 "AI가 더 좋은 코드를 쓴다"가 아니라 "AI가 개발 프로세스 자체를 다르게 설계한다"는 쪽이다. 비동기·병렬 처리라는 구조가, 개발자의 역할을 '코드 작성자'에서 '검토자'로 옮기는 첫 번째 현실적 시도다.
