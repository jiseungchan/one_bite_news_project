## 한 줄 요약
> AI 에이전트 한 마리가 혼자 뛰던 시대에서, Opus 4.8은 수백 마리를 동시에 지휘하는 오케스트라 구조로 전환했다.

## 리드 — 왜 지금 이게 중요한가?

Anthropic이 2026년 5월 28일 Claude Opus 4.8을 출시했다. 가장 큰 변화는 'Dynamic Workflows'라는 신기능이다. 하나의 세션 안에서 최대 동시 16개, 총 1,000개의 서브에이전트(sub-agent — 큰 작업을 나눠서 처리하는 개별 AI 실행 단위)를 병렬로 돌릴 수 있다. 지금까지 AI 에이전트 작업은 순차 처리가 기본이었다. Opus 4.8은 그 전제를 바꿨다.

## 배경 — 기존에는 어땠나?

AI 에이전트는 복잡한 작업을 처리할 때 단계별로 하나씩 처리하는 방식이 일반적이었다. "코드 분석 → 버그 탐지 → 수정안 제안"처럼 앞 단계가 끝나야 다음 단계로 넘어간다. 이 구조는 태스크가 늘어날수록 처리 시간이 선형으로 증가하는 문제가 있었다.

기업 현장에서 AI 코딩 에이전트나 문서 분석 에이전트를 실무에 투입하려 할 때 속도 병목은 현실적인 장벽이었다. 병렬 실행을 구현하려면 개발자가 직접 여러 API 호출을 조율하는 복잡한 오케스트레이션 코드를 짜야 했고, 이 과정 자체가 많은 엔지니어링 리소스를 요구했다.

## 핵심 — 무엇이 다른가?

Opus 4.8의 Dynamic Workflows는 JavaScript 스크립트를 통해 수백 개의 서브에이전트를 자동으로 스폰(spawn — 새로운 실행 단위를 만드는 것)하고 병렬 실행한다. 개발자가 별도의 오케스트레이션 로직을 짤 필요 없이, 큰 작업을 정의하면 Opus 4.8이 스스로 작업을 분해해 서브에이전트에 분배한다.

마치 한 명의 프로젝트 매니저가 수백 명의 팀원에게 동시에 각자의 업무를 배분하는 것과 같은 구조다.

| 항목 | 기존 에이전트 방식 | Claude Opus 4.8 |
|------|----------------|----------------|
| 실행 방식 | 순차 처리 | 최대 16개 동시 병렬 |
| 서브에이전트 상한 | 별도 오케스트레이션 필요 | 세션당 최대 1,000개 |
| 비용 (Fast Mode) | 기준 1x | 3배 저렴, 2.5× 속도 |
| 불확실성 처리 | 추정 기반 진행 | 불확실 시 명시적 플래그 |

Fast Mode는 이전 대비 3배 저렴해졌고 처리 속도는 2.5배 빠르다. Effort Controls(노력 수준 조절)는 사용자가 태스크별로 얼마나 깊이 있게 처리할지를 직접 지정할 수 있는 기능이다 — 단순 작업에는 빠른 처리, 복잡한 추론에는 높은 노력 수준으로 설정하는 방식이다.

신뢰성 측면에서도 개선이 있었다. Opus 4.8은 에이전트 태스크 수행 중 불확실한 판단이 필요한 상황에서 근거 없이 진행하는 대신 명시적으로 플래그를 올리는 방향으로 설계됐다.

## 시장 영향 — 어디에 쓰이나?

- **코드 엔터프라이즈 워크플로**: Claude Code Enterprise/Team/Max 플랜 사용자가 우선 대상. 대규모 코드베이스 분석, 테스트 자동화, 멀티 파일 리팩토링에 직접 적용 가능
- **벤치마크**: Super-Agent 벤치마크(복잡한 멀티스텝 에이전트 태스크를 엔드투엔드로 완료하는 능력을 측정하는 평가 지표)에서 모든 케이스를 완주한 유일한 모델로 소개됐다
- **비용 경쟁력**: 가격은 기존 Opus 4.7과 동일한 입력 $5/백만 토큰, 출력 $25/백만 토큰 수준으로, GPT-5.5 대비 같은 비용에서 에이전트 성능 우위를 주장한다
- 영향 산업: 소프트웨어 개발, 법률 문서 검토, 금융 데이터 분석 등 반복적·병렬 처리 가능한 지식노동 전반

## 병규의 한 줄

이번 업데이트에서 흥미로운 건 속도나 성능 수치보다 구조 철학이다. Anthropic은 '더 똑똑한 단일 에이전트'가 아니라 '더 많은 에이전트를 더 쉽게 다루는 프레임워크'에 베팅했다 — AI 성능의 한계를 모델 자체보다 오케스트레이션 레이어에서 돌파하겠다는 선택이다.
