## 한 줄 요약
> 구글 버텍스 AI가 에이전트 기억(Memory Bank)에 자동 만료 기능을 추가해, AI가 시간이 지난 정보를 스스로 폐기할 수 있게 됐다.

## 리드 — 왜 지금 이게 중요한가?

2026년 7월 7일, 구글의 기업용 AI 플랫폼 버텍스 AI(Vertex AI — 구글 클라우드에서 제공하는 AI 모델 훈련·배포 통합 플랫폼)가 SDK v1.160.0을 내놓았다. 이번 업데이트의 핵심은 메모리 뱅크(Memory Bank)의 IngestEvents API에 TTL(Time To Live — 정보의 유효 기간)과 만료 시간을 설정하는 기능이 추가됐다는 것이다. AI 에이전트의 기억이 단순 저장을 넘어 '살아있는 정보'처럼 관리되는 방향으로 바뀌고 있다.

## 배경 — 기존에는 어땠나?

AI 에이전트에게 기억을 부여하는 방식은 크게 두 가지다. 외부 벡터 데이터베이스(벡터DB)를 연결하는 방식, 그리고 플랫폼 내장 메모리를 쓰는 방식이다. 구글 버텍스 AI는 후자 방식의 메모리 뱅크를 제공해왔는데, 문제가 있었다. 한 번 저장된 정보는 영구적으로 유지됐다.

실용적인 어려움은 금세 드러났다. "이번 달 예산은 500만 원"이라는 기억을 심어두면 다음 달에도 같은 값이 남아 에이전트가 잘못된 판단을 내릴 수 있다. 환율, 규정, 인원 변동처럼 시간에 따라 달라지는 정보를 에이전트 메모리에 넣으면 개발자가 수동으로 삭제하지 않는 한 낡은 데이터가 계속 살아남는 문제였다.

## 핵심 — 무엇이 다른가?

이번 업데이트에서 추가된 IngestEvents API 신규 파라미터:

| 파라미터 | 기능 |
|---------|------|
| `revision_ttl` | 메모리 리비전의 생존 기간 설정 |
| `revision_expire_time` | 특정 날짜·시간에 메모리 자동 만료 |
| `revision_labels` | 리비전에 분류 레이블 부착 |
| `disable_memory_revisions` | 특정 이벤트에서 메모리 업데이트 차단 |
| `metadata` | 메모리에 구조화된 메타데이터 추가 |
| `metadata_merge_strategy` | 메타데이터 병합 방식 제어 |
| `overlap_event_count` | 중복 이벤트 처리 횟수 설정 |

`revision_ttl`과 `revision_expire_time`의 차이는 이렇다. TTL은 "추가한 시점으로부터 30일 후 삭제"처럼 상대적 기간을, expire_time은 "2026년 8월 1일 00:00에 삭제"처럼 절대 시각을 지정한다. 냉장고에 식품을 넣을 때 "3일 후 버려"라고 적는 것(TTL)과 "8월 1일에 버려"라고 적는 것(expire_time)의 차이와 같다.

`metadata_merge_strategy`는 기존 메타데이터 위에 새 정보를 덮어쓸지, 병합할지, 충돌 시 어떻게 처리할지를 결정한다. 에이전트가 동일 사용자에 대한 정보를 여러 세션에서 쌓아갈 때 일관성을 유지하는 데 핵심적인 기능이다.

이번 릴리스에는 Gemini Agents API에 평가(eval) 에이전트 유형도 추가됐다. 에이전트의 응답 품질을 측정하는 전용 평가 시스템이 플랫폼 내장 기능으로 제공된다는 의미다. 버텍스 Model Garden에서는 퍼블리셔(외부 AI 기업)가 공개한 모델의 배포 옵션을 조회하는 `list_publisher_model_deploy_options` 메서드도 추가됐다.

## 시장 영향 — 어디에 쓰이나?

에이전트 메모리 TTL 관리는 정보의 최신성이 곧 신뢰성인 도메인에서 특히 가치가 있다.

- **금융**: "오늘의 기준금리", "이번 분기 규제 변경"처럼 갱신이 잦은 정보를 자동 만료
- **의료**: 일시적 복약 정보나 검진 결과가 기간 만료 후 자동 폐기
- **기업 운영**: 프로젝트 단위 맥락 정보가 프로젝트 종료 후 자동 정리

앞서 Gemini Agents 평가 시스템의 추가는 에이전트 품질 관리를 외부 도구 없이 플랫폼 안에서 처리할 수 있게 됐다는 점에서 엔터프라이즈 도입 장벽을 낮추는 효과가 있다.

## 병규의 한 줄

흥미로운 건, 구글과 앤트로픽이 같은 주에 각자의 에이전트 메모리 시스템을 독립적으로 확장했다는 사실이다. 업계 전체가 동시에 같은 문제 — '기억하는 AI를 어떻게 실용적으로 만들 것인가' — 를 푸는 중이라는 신호다.
