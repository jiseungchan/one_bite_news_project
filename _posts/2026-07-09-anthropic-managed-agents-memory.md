## 한 줄 요약
> 앤트로픽이 세션이 끊겨도 기억이 유지되는 메모리 저장소 API와 배포·스케줄링이 가능한 관리형 에이전트 플랫폼을 한꺼번에 베타로 공개했다.

## 리드 — 왜 지금 이게 중요한가?

6월 말부터 7월 초, 앤트로픽의 개발자 SDK에 조용하지만 의미 있는 변화가 생겼다. 대화 세션이 끊겨도 기억을 유지하는 '메모리 저장소(Memory Store)' API가 베타로 추가됐고, 에이전트를 스케줄에 따라 자동 실행하거나 여러 에이전트가 함께 조율하며 작동하는 '관리형 에이전트(Managed Agents)' 플랫폼이 함께 공개됐다(SDK v0.115.0 ~ v0.116.0, 2026-06-30~07-02). 에이전트가 기억과 자율성을 동시에 갖추는 방향으로 클로드 생태계가 빠르게 움직이고 있다.

## 배경 — 기존에는 어땠나?

지금까지 LLM(대규모 언어 모델) 기반 AI 에이전트의 가장 큰 한계는 "대화가 끝나면 모든 걸 잊는다"는 점이었다. 사용자가 어떤 선호를 말했든, 프로젝트 맥락을 설명했든 새 세션이 시작되는 순간 백지 상태로 돌아간다. 기억이 없는 에이전트는 매일 출근할 때마다 자신이 누구인지 잊어버리는 직원과 같다.

에이전트 기억을 구현하려면 개발자가 직접 벡터 데이터베이스(벡터DB — 의미 기반 검색을 위한 고차원 수치 저장소)를 붙이고 동기화 로직을 직접 만들어야 했다. 이 구조는 복잡하고, 에이전트와 메모리 저장소 사이의 연동을 개발자가 전적으로 책임져야 하는 부담이 있었다.

## 핵심 — 무엇이 다른가?

앤트로픽의 새 메모리 저장소는 에이전트 간, 세션 간 공유 가능한 영구 저장소다. 개발자가 메모리 항목을 직접 추가·수정·삭제·보관할 수 있고, 변경 이력도 버전별로 추적된다. 가장 주목할 점은 저장소의 '설명(description)' 필드(최대 1,024자)가 에이전트 시스템 프롬프트에 **자동 삽입**된다는 것이다. 즉, "이 에이전트는 사용자가 채식주의자이며 마감에 민감하다는 것을 알고 있다"는 맥락을 별도 코드 없이 에이전트의 기반 지식으로 만들 수 있다.

관리형 에이전트 플랫폼의 주요 사양:

| 항목 | 사양 |
|------|------|
| 도구(Tools) | 에이전트당 최대 128개 |
| MCP 서버 연결 | 에이전트당 최대 20개 |
| 배포 스케줄 | POSIX cron 5필드 형식 |
| 세션 리소스 | GitHub 저장소, 파일, 메모리 저장소 |
| 자격증명 | Vault를 통한 안전 주입 |
| 멀티에이전트 | 조율자(coordinator) 토폴로지 지원 |

MCP 서버(Model Context Protocol — 외부 AI 도구를 표준 방식으로 연결하는 규격)를 최대 20개까지 붙일 수 있어, 에이전트가 웹 검색·코드 실행·데이터베이스 조회 등 복합 도구를 동시에 활용할 수 있다. 에이전트·배포 이벤트를 외부 시스템에 실시간 전달하는 웹훅도 포함됐다. 베타 헤더 식별자는 `anthropic-beta: agent-memory-2026-07-22`다.

## 시장 영향 — 어디에 쓰이나?

이전까지 에이전트 메모리 구현은 개발자가 직접 외부 저장소를 연동해야 했다. 이 기능이 클로드 API에 내장되면 별도 인프라 없이도 기억하는 에이전트를 만들 수 있다. POSIX cron 스케줄 배포는 "매일 오전 9시 뉴스를 정리해서 Slack에 올린다", "매주 월요일 지난주 업무를 분석한다" 같은 반복 자동화 워크플로에 바로 활용할 수 있는 기능이다. 개인 비서형 에이전트, 엔터프라이즈 자동화 봇, 지속적 모니터링 에이전트 모두 이 플랫폼의 적용 대상이다.

## 병규의 한 줄

이번 릴리스에서 흥미로운 건 기능 목록보다 설계 철학이다. '메모리 설명을 시스템 프롬프트에 자동 삽입한다'는 구조는 메모리를 외부 저장소가 아니라 에이전트 정체성의 일부로 취급하겠다는 선택이다.
