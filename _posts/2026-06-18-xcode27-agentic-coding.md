## 한 줄 요약
> Xcode 27의 코딩 에이전트는 단순 자동완성을 넘어, 프로젝트 전체를 읽고 설계하고 테스트까지 돌린다 — 개발자는 목표만 말하면 된다.

## 리드 — 왜 지금 이게 중요한가?

이번 WWDC 2026(6월 8~12일)에서 Apple이 공개한 Xcode 27에는 꽤 달라진 게 있다. AI 에이전트가 코드 작성 전 단계부터 마무리까지 붙어서 돕는 구조가 생겼다. 기존 AI 코딩 도구들이 커서 위치 기준으로 한 줄씩 제안하는 방식이었다면, Xcode 27은 프로젝트 전체 맥락을 읽고 계획을 세운 뒤 실행하는 방식으로 작동한다.

## 배경 — 기존에는 어땠나?

지금까지 AI 코딩 도구의 주된 역할은 자동완성(autocomplete)이었다. GitHub Copilot이나 기존 Xcode의 코드 완성 기능 모두 개발자가 타이핑하는 위치에서 다음 줄을 제안하는 방식이다. 유용하긴 하지만 개발자가 "어디에 무엇을 쓸지"를 이미 알고 있어야 한다는 전제가 있다.

새 프로젝트를 처음 열거나, 수만 줄짜리 레거시 코드를 파악해야 할 때, 또는 번역·접근성 작업처럼 반복적이지만 전체 파일을 건드려야 하는 작업에서는 여전히 개발자가 대부분의 판단을 직접 해야 했다. AI가 "보조자" 수준에 머물렀던 이유다.

## 핵심 — 무엇이 다른가?

Xcode 27의 에이전트는 개발 과정을 4단계로 나눠 작동한다.

**탐색(Explore)** — 프로젝트를 처음 열면 에이전트가 전체 구조를 분석하고 아키텍처 문서를 자동으로 생성한다. Apple Document Search(애플 공식 API 문서를 실시간으로 검색하는 기능)를 통해 최신 프레임워크 사용법도 참조한다.

**구축(Build)** — Plan Mode에서 코드 작성 전에 먼저 설계를 제안하고, 개발자가 승인하면 실제 구현에 들어간다. 빌드 오류가 나면 에이전트가 직접 감지하고 수정을 반복한다.

**정제(Refine)** — 스케치 이미지나 디자인 파일을 첨부하면 에이전트가 의도를 파악해 UI에 반영한다. Inline Annotations(소스 코드 특정 위치에 직접 지시를 남기는 기능)를 통해 "이 부분만 이렇게 바꿔달라"는 정밀한 요청도 가능하다.

**조율(Orchestrate)** — 가장 흥미로운 부분이다. "필리핀어로 번역하고 VoiceOver 접근성 레이블도 추가해줘"처럼 고수준 목표를 주면, 서브-에이전트(하위 작업을 담당하는 별도 AI 인스턴스)들이 각 작업을 병렬로 처리한다. 개발자가 일일이 파일을 열고 문자열을 찾는 작업이 사라진다.

| 구분 | 기존 방식 | Xcode 27 에이전트 |
|------|-----------|------------------|
| 탐색 | 개발자가 직접 코드 읽기 | 에이전트가 구조 분석 후 문서 생성 |
| 코드 작성 | 자동완성 제안 | 계획 수립 후 구현·테스트 |
| UI 수정 | 수동으로 파일 찾아 편집 | 이미지 첨부로 의도 전달 |
| 반복 작업 | 개발자가 직접 처리 | 서브-에이전트 병렬 처리 |

비유하자면, 기존 AI 도구가 "옆에 앉은 타이피스트"였다면 Xcode 27의 에이전트는 "프로젝트 전체를 이해하는 주니어 개발자"에 가깝다.

## 시장 영향 — 어디에 쓰이나?

- iOS/macOS 앱 개발 전 과정에 적용 가능
- 특히 현지화(번역), 접근성(VoiceOver 레이블) 같은 반복 작업에서 시간 절약 기대
- 같은 WWDC26에서 공개된 Core AI(온디바이스 AI 추론 프레임워크)와 연계해, 앱 내 AI 기능을 서버 없이 기기 안에서 구동하는 흐름도 함께 만들어지고 있다

## 병규의 한 줄

이번에 눈에 띄는 건 "에이전트가 코드를 잘 쓰냐"가 아니라 "에이전트가 프로젝트를 이해하고 목표 단위로 일하느냐"다. Apple은 조율(Orchestrate) 단계에서 서브-에이전트 병렬 구조를 선택했는데, 이건 AI 코딩 도구를 보조 입력 수단에서 작업 실행 주체로 재정의하려는 시도다.
