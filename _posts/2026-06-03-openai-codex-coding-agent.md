## 한 줄 요약
> Codex는 '같이 코딩하는 AI'가 아니라 '대신 코딩하는 AI'다 — 개발자가 지시를 내리고 결과만 검토하는 방식으로 협업 구조가 바뀌다.

## 리드 — 왜 지금 이게 중요한가?

OpenAI가 2026년 5월 말 클라우드 기반 코딩 에이전트(agent — 다단계 작업을 스스로 계획하고 실행하는 AI 시스템) 'Codex'를 ChatGPT Pro·Team 구독자에게 공개했다. 기존 AI 코딩 도구들이 개발자 옆에 않아 코드를 제안하는 '보조' 역할이었다면, Codex는 클라우드 샌드박스(sandbox — 외부 시스템과 격리된 실험 환경)에서 독립적으로 작업을 완수한 뒤 결과물만 돌려주는 방식이다. 개발자가 자리를 비운 사이에도 코딩을 계속한다.

## 배경 — 기존에는 어땠나?

GitHub Copilot(2021년 출시), Cursor(2023년 출시) 같은 AI 코딩 보조 도구들은 개발자의 화면 옆에 붙어 실시간으로 코드를 제안하는 방식이었다. 마치 페어 프로그래밍(pair programming — 두 명이 한 화면을 보며 함께 코딩하는 개발 방식)의 AI 버전이었다.

이 방식의 한계는 개발자가 계속 자리를 지켜야 한다는 점이다. AI가 제안을 해도 수낙·거부는 사람이 매번 판단해야 했고, 복잡한 멀티파일(여러 파일에 걸친) 수정이나 테스트 실행은 별도로 처리해야 했다. AI가 빠른 보조자는 떐지만, 독립적인 실행자는 아니었다.

SWE-bench Verified(실제 GitHub 이슈를 자율적으로 해결하는 능력을 측정하는 소프트웨어 엔지니어링 벤치마크) 기준으로 2024년 초 최고 성능 AI의 작업 성공률은 약 18%였다. 그로부터 1년여 만에 이 수치는 50%를 넘겼다.

## 핵심 — 무엇이 다른가?

Codex의 핵심 차이는 **비동기(asynchronous) 실행**이다. 사용자가 작업을 지시하면 Codex는 클라우드의 격리된 가상 환경에서 독립적으로 실행된다. 작업이 끽나면 결과물(코드, 테스트 통과 여부, PR 초안)을 사용자에게 전달한다.

동작 방식을 단계별로 보면:
1. 사용자가 자연어로 작업 지시 ("이 함수의 엣지 케이스 처리하고 테스트 추가해줘")
2. Codex가 코드베이스를 읽고 변경 계획 수립
3. 샌드박스 환경에서 코드 수정 → 테스트 실행 → 오류 발생 시 자동 수정 반복
4. 완성된 변경 사항과 테스트 결과를 사용자에게 전달
5. 사용자가 검토 후 머지(merge — 변경 사항을 메인 코드에 통합) 결정

| 항목 | 기존 AI 코딩 도구 | Codex |
|------|----------------|-------|
| 작업 방식 | 동기 — 사용자가 매 단계 확인 | 비동기 — 완료 후 결과 전달 |
| 실행 환경 | 로칼(개발자 PC) | 클라우드 샌드박스 |
| 병렬 처리 | 1개 작업 | 여러 작업 동시 실행 가능 |
| 테스트 실행 | 수동 | 자동 (결과 포함 반환) |

## 시장 영향 — 어디에 쓰이나?

- 현재 ChatGPT Pro($200/월), Team 플랜 구독자 대상으로 먼저 공개됐으며, Enterprise 확장 예정
- 소규모 스타트업이나 개인 개발자가 시니어 개발자 없이 복잡한 코드베이스를 유지관리하는 데 활용 기대
- OpenAI는 Codex를 o3 모델 기반으로 구동한다고 밝혀다 — 추론(reasoning) 능력에 특화된 모델이다
- GitHub, Atlassian 등 개발 플랫폼과의 통합이 향후 핵심 경쟁 구도로 부상할 전망

## 병규의 한 줄

이번에 흥미로운 건 Codex가 '더 릍나한 자동완성'이 아니라 '위임 가능한 동료'를 목표로 설계됐다는 점이다. 개발자가 AI에게 코드를 제안받던 시대에서, 작업을 맡기고 결과를 검토하는 시대로 — 그 전환이 생각보다 조용히 진행되고 있다.
