## 한 줄 요약
> 깃허브 코파일럿 워크스페이스는 코드 자동완성을 넘어, 이슈에서 완성된 풀 리퀘스트까지 AI가 단독으로 처리하는 첫 번째 상용 코딩 에이전트다.

## 리드 — 왜 지금 이게 중요한가?

깃허브가 2026년 6월 'Copilot Workspace(코파일럿 워크스페이스)'를 베타 종료 후 전 사용자 대상으로 정식 출시했다. 개발자가 버그 이슈 티켓 번호만 입력하면, AI가 코드베이스를 분석하고 수정 계획을 제안한 뒤 실제 코드를 작성해 풀 리퀘스트(PR — 코드 변경 사항을 팀에 검토 요청하는 절차)까지 생성한다. 사람은 최종 검토만 하면 된다.

## 배경 — 기존에는 어땠나?

코파일럿의 초기 형태는 코드 자동완성 도구였다. 개발자가 함수 이름이나 주석을 입력하면 다음 줄을 제안하는 방식으로, 2021년 출시 당시만 해도 혁신적이었다. 그러나 실제 개발 업무는 코드 작성 자체보다 이슈 분석, 영향 범위 파악, 테스트 계획 수립에 더 많은 시간이 든다.

깃허브가 2024년 발표한 내부 데이터에 따르면, 개발자의 하루 업무 중 실제 코드 타이핑에 쓰는 시간은 평균 18%에 불과하다. 나머지 82%는 이해·검토·커뮤니케이션이다. 코파일럿 1세대는 18%만 도왔다. 워크스페이스는 나머지를 공략한다.

## 핵심 — 무엇이 다른가?

코파일럿 워크스페이스의 작동 방식은 다음과 같다:

1. **이슈 파싱**: GitHub 이슈 또는 JIRA 티켓을 읽어 문제를 자연어로 해석
2. **코드베이스 분석**: 관련 파일, 함수, 의존성(dependency)을 자동 파악
3. **수정 계획 제안**: 어떤 파일을 어떻게 바꿀지 단계별로 제시 (사람이 검토 후 승인)
4. **코드 작성 및 PR 생성**: 승인된 계획대로 코드 작성 후 자동으로 PR 생성

기존 코파일럿과의 차이는 단순 보조에서 에이전트(스스로 판단하고 실행하는 AI)로의 전환이다.

| 구분 | 코파일럿 (기존) | 코파일럿 워크스페이스 |
|------|---------------|-------------------|
| 입력 | 현재 줄의 코드 컨텍스트 | GitHub 이슈 전체 |
| 출력 | 다음 줄 코드 제안 | 완성된 PR |
| 판단 범위 | 현재 함수 내 | 전체 코드베이스 |
| 사람 개입 | 매 줄마다 | 계획 승인 1회 |

깃허브는 내부 테스트에서 단순 버그 수정 작업의 소요 시간이 평균 67% 감소했다고 밝혔다.

## 시장 영향 — 어디에 쓰이나?

- GitHub Copilot Enterprise 플랜(월 39달러) 가입자 전체에 즉시 제공
- 중소 스타트업의 유지보수 엔지니어링 비용 절감 효과가 가장 클 것으로 전망
- 커서(Cursor), 윈드서프(Windsurf) 등 AI 코딩 에디터 스타트업과의 경쟁이 본격화될 전망
- 한국의 네이버, 카카오, 쿠팡 등 대형 IT 기업도 GitHub Enterprise 사용자로 즉시 활용 가능

## 병규의 한 줄

코파일럿 워크스페이스가 흥미로운 건 개발 속도가 아니라 업무 구조의 변화다. 이슈를 PR로 바꾸는 과정 전체를 AI가 담당한다면, 개발자의 역할은 '코드를 쓰는 사람'에서 '코드와 비즈니스 요구사항 사이를 중재하는 사람'으로 바뀐다. 그 전환이 얼마나 빠르게, 얼마나 폭넓게 일어날지가 이제 진짜 질문이다.
