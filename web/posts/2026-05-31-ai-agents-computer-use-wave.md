## 한 줄 요약
> AI 에이전트가 단순히 '답변'을 주는 것을 넘어, 직접 컴퓨터를 조작하는 단계로 진입하고 있다 — 이 전환이 어디까지 갈 수 있는지가 지금 업계의 핵심 질문이다.

## 리드 — 왜 지금 이게 중요한가?

올해 상반기를 기점으로 주요 AI 기업들이 'computer-use(컴퓨터 직접 제어)' 기능을 자사 모델에 통합하기 시작했다. 단순히 질문에 답하는 것이 아니라, AI가 직접 브라우저를 열고, 폼을 작성하고, 파일을 이동시키는 방식이다. Anthropic의 클로드, OpenAI의 오퍼레이터, 구글의 Project Mariner가 각자의 방식으로 이 영역에 진입했고, 스타트업들도 빠르게 뒤를 따르고 있다. MIT Technology Review는 이 흐름을 "AI 에이전트의 두 번째 물결"로 규정했다.

## 배경 — 기존에는 어땠나?

지금까지 AI 모델은 텍스트나 이미지를 입력받아 텍스트를 출력하는 구조였다. 사용자가 "이 스프레드시트를 정리해줘"라고 하면, AI는 어떻게 하면 되는지 설명하거나 코드를 제안하는 수준에 머물렀다. 실제 파일을 열고 수정하는 건 여전히 사람의 몫이었다.

이 구조의 한계는 분명했다. 지식 노동자들이 하루에 소비하는 시간 중 상당 부분은 반복적인 디지털 작업 — 이메일 정리, 양식 제출, 데이터 복사 붙여넣기 — 이다. AI가 아무리 좋은 답변을 내놔도, 그 답변을 실행에 옮기는 과정은 여전히 사람이 처리해야 했다. "AI는 조언만 하고 일은 사람이 한다"는 구조가 고착화되어 있었다.

## 핵심 — 무엇이 다른가?

computer-use 에이전트의 핵심은 AI가 화면(스크린샷)을 이해하고, 마우스 클릭과 키보드 입력을 직접 생성하는 방식이다. 단계별로 보면 이렇다.

1. 사용자가 목표를 자연어로 입력한다 ("항공편 예약하고 캘린더에 추가해줘")
2. AI가 현재 화면 상태를 스크린샷으로 인식한다
3. 다음에 해야 할 동작(클릭 위치, 타이핑 내용)을 결정한다
4. 결과 화면을 다시 확인하며 목표 달성 여부를 판단한다

| 항목 | 기존 AI 어시스턴트 | computer-use 에이전트 |
|------|-----------------|-------------------|
| 실행 방식 | 지침 제공 (사람이 실행) | 직접 실행 |
| 작업 범위 | 단일 턴 응답 | 멀티스텝 연속 작업 |
| 오류 처리 | 불가 (실행 없음) | 화면 확인 후 재시도 |
| 필요 권한 | 없음 | 시스템 접근 권한 필요 |

마치 전화로 심부름을 시키던 것에서, 직접 대신 나가서 일을 처리해 오는 것으로 바뀐 셈이다.

## 시장 영향 — 어디에 쓰이나?

- Anthropic 클로드의 computer-use 기능, 기업 고객 대상 베타 성공률 약 70~80% (단순 반복 작업 기준)
- OpenAI 오퍼레이터(Operator), 여행 예약·온라인 쇼핑 등 소비자 시나리오에서 초기 테스트 중
- 가장 큰 수혜 직군: 데이터 입력, 고객 지원, 행정 업무 등 반복적 디지털 작업이 많은 분야
- 보안 리스크도 동시에 제기됨 — AI가 시스템 접근 권한을 갖는 만큼, 악의적 지시나 프롬프트 인젝션(prompt injection, 외부 콘텐츠를 통해 AI의 행동을 몰래 바꾸는 공격) 취약점이 새로운 과제로 부상

## 병규의 한 줄

이번에 흥미로운 건 기술 자체보다 그 설계 철학이다. 지금까지 AI는 "더 나은 검색"이나 "더 빠른 초안 작성" 도구였다면, computer-use는 처음으로 AI를 사람의 업무 흐름 안으로 끌어들이는 시도다 — 이게 통하면, 인간-AI 협업의 기본 단위 자체가 바뀐다.
