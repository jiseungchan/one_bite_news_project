## 한 줄 요약
> OpenAI의 Codex는 단순한 코드 완성 도구가 아니라, 스스로 작업 목록을 소화하고 결과물을 GitHub에 올리는 '자율 개발자' 에이전트다.

## 리드 — 왜 지금 이게 중요한가?

OpenAI가 클라우드에서 완전 자율로 실행되는 코딩 에이전트 Codex를 공개했다. 기존 GitHub Copilot처럼 코드를 제안하는 수준이 아니라, 독립된 샌드박스(격리된 실행 환경) 안에서 기능 구현·버그 수정·테스트 실행까지 모두 마친 뒤 Pull Request(PR, 코드 변경 요청)를 직접 생성한다. 개발자가 아침에 작업 목록을 던져두면 Codex가 병렬로 처리하는 구조다.

## 배경 — 기존에는 어땠나?

지금까지 AI 코딩 도구의 주력은 자동완성(autocomplete) 방식이었다. 개발자가 코드를 작성하는 동안 옆에서 다음 줄을 제안하는 형태로, GitHub Copilot이 이 시장을 개척했다. 2021년 출시 이후 수백만 명의 개발자가 사용하고 있지만 근본적인 한계는 분명했다. AI는 여전히 개발자의 흐름 안에 있어야 했다. 사람이 방향을 잡고, AI는 문장을 채우는 역할이었다.

2023~2024년에는 한 단계 나아가 '에이전트 코딩' 시도가 늘었다. Devin(코그니션 AI가 만든 자율 코딩 에이전트), Cursor, Aider 같은 도구들이 등장해 더 복잡한 작업을 맡겼지만, 대부분 로컬 개발 환경에서 사람이 지켜보는 상태에서 작동했다. 결과물을 신뢰하려면 매 단계를 확인해야 했고, 긴 작업을 맡겼을 때 중간에 방향을 잃는 경우도 많았다.

OpenAI의 Codex는 이 방정식을 다시 쓰려는 시도다. 클라우드에서 완전히 격리된 환경을 만들고, 에이전트가 그 안에서 자율적으로 작업을 완료한 뒤 검토 가능한 형태(PR)로 돌아오도록 설계했다.

## 핵심 — 무엇이 다른가?

Codex의 핵심 설계 원칙은 '비동기 실행'이다. 사람이 지켜보지 않아도 되는 방식이다.

작동 방식은 크게 세 단계다.

1. 개발자가 자연어로 작업을 지시한다 ("결제 모듈의 환불 로직을 수정하고 엣지 케이스 테스트를 추가해줘").
2. Codex가 격리된 클라우드 샌드박스에서 코드베이스를 읽고, 변경 사항을 작성하고, 테스트를 실행하고, 오류를 직접 수정한다.
3. 작업이 완료되면 GitHub에 PR을 자동 생성하고, 변경 이유와 테스트 결과를 함께 기록한다.

| 항목 | 기존 AI 코딩 도구 | Codex |
|------|-----------------|-------|
| 실행 환경 | 로컬 개발 환경 | 클라우드 격리 샌드박스 |
| 작업 방식 | 사람이 지켜보며 단계별 확인 | 비동기 — 완료 후 결과물 전달 |
| 병렬 처리 | 한 번에 1작업 | 여러 작업 동시 처리 |
| 결과물 형태 | 인라인 코드 제안 | GitHub PR (변경 이유 포함) |

OpenAI는 Codex에 o3(추론에 특화된 모델) 기반의 새 버전 'codex-1'을 탑재했다. SWE-bench Verified(실제 소프트웨어 이슈 해결 능력을 측정하는 벤치마크)에서 기존 도구보다 높은 성능을 기록했다고 밝혔다.

## 시장 영향 — 어디에 쓰이나?

- ChatGPT Pro, Team, Enterprise, Plus 구독자에게 단계적으로 제공 예정
- 개발팀의 반복적 작업(버그 수정, 리팩토링, 테스트 추가)을 에이전트에 위임 가능
- 소규모 팀이나 1인 개발자에게 사실상 '추가 개발자' 한 명을 두는 효과
- SWE-bench 벤치마크 기준으로 Devin(코그니션 AI)과 직접 경쟁 구도

## 병규의 한 줄

이번 Codex에서 눈여겨볼 건 '에이전트가 잘하냐'보다 'PR이라는 형식을 결과물로 택했다'는 설계 결정이다. 사람이 검토 가능한 단위로 돌아오도록 만든 것은 자율성과 신뢰 사이의 절충을 어떻게 풀었는지를 보여준다.
