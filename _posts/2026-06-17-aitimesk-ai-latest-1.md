## 배경

AI 에이전트(AI Agent — 사람 대신 복잡한 작업을 자율적으로 수행하는 AI 시스템)가 실용화되려면 두 가지 조건이 필요하다. 첫째, 웹사이트를 실제로 조작할 수 있어야 한다. 둘째, 너무 많은 컴퓨팅 자원을 쓰지 않아야 한다.

문제는 이 두 조건이 서로 충돌한다는 점이다. GPT-4급 대형 모델(LLM — 수천억 개 이상의 파라미터를 가진 대형 언어 모델)은 복잡한 추론은 잘 하지만 운영 비용이 높다. 반면 소형 모델은 저렴하지만 여러 단계에 걸친 웹 조작 작업에서 성능이 급격히 떨어진다는 게 업계의 통념이었다. 소형 모델은 맥락(컨텍스트)이 길어질수록 앞서 받은 정보를 제대로 활용하지 못하는 한계가 있어서다.

## 핵심

마이크로소프트 리서치 AI Frontiers 팀이 2026년 5월 공개한 MagenticLite는 이 문제를 역할 분리로 풀었다. 대형 모델 하나가 모든 걸 하는 대신, 작은 모델 두 개가 각자 잘하는 일을 맡는 구조다.

**MagenticBrain**(14B 파라미터 — 140억 개의 학습 가중치를 가진 모델, Qwen 3 14B 기반)이 큰 그림을 담당한다. 계획을 세우고, 코드를 짜고, 서브에이전트에게 작업을 위임하는 역할이다. **Fara1.5**(4B·9B·27B 세 가지 버전)는 실제 브라우저를 열고 웹페이지를 클릭하는 실행 역할을 맡는다.

이 둘을 연결하는 핵심 설계가 **활성 컨텍스트 관리**다. 소형 모델에게 모든 이전 대화 내용을 던져주는 대신, 현재 단계에서 필요한 정보만 선별해 전달한다. 마치 주방에서 수셰프가 파티시에에게 레시피 전체 대신 "지금 당장 필요한 재료만" 건네주는 것과 같은 원리다.

| 구분 | 기존 방식 | MagenticLite |
|---|---|---|
| 역할 구조 | 대형 모델 1개가 전담 | 오케스트레이터 + 실행 에이전트 분리 |
| 컨텍스트 처리 | 전체 맥락 그대로 전달 | 단계별 필요 정보만 선별 전달 |
| 민감 작업 처리 | 자동 실행 | 임계점 감지 후 사용자 승인 요청 |
| 웹 네비게이션 성능 | Fara-7B 기준 | 거의 2배 향상 |

Fara1.5는 기능도 강화됐다. 결제 완료, 로그인, 되돌릴 수 없는 양식 제출처럼 실수하면 곤란한 **임계점**을 스스로 감지하고, 계속 진행하기 전에 사용자에게 확인을 구한다.

## 시장 영향

- Online-Mind2Web 벤치마크(웹 브라우징 자동화 능력을 측정하는 표준 평가 지표)에서 Fara1.5-27B가 90% 이상 성능을 기록하며 동급 모델 최고치를 달성했다
- 이전 Fara-7B 대비 웹 네비게이션 성능이 거의 2배 향상됐다
- MagenticLite 코드는 GitHub에 공개됐고, MagenticBrain과 Fara1.5는 Microsoft Foundry를 통해 접근 가능하다
- 현재 연구 목적의 실험적 릴리스로 커뮤니티 피드백을 수집 중이다

## 병규의 한 줄

이번 설계에서 흥미로운 건 "더 큰 모델이 더 잘한다"는 전제를 뒤집었다는 점이다. 성능 향상의 열쇠가 파라미터 수가 아니라 "어떤 정보를 언제 보여주느냐"는 오케스트레이션에 있다는 걸 수치로 증명한 사례다.
