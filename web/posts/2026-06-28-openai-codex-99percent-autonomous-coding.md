## 한 줄 요약
> 오픈AI 직원들이 챗봇을 버리고 자율 에이전트 Codex로 갈아탄 결과, 사내 AI 업무의 99%가 Codex 한 곳에서 처리된다.

## 리드 — 왜 지금 이게 중요한가?

오픈AI가 스스로 밝혔다. 자사 직원들이 처리하는 AI 관련 업무의 99%가 이제 ChatGPT 같은 챗봇이 아니라 자율 코딩 에이전트 Codex를 통해 이뤄진다고. AI 개발사 안에서도 "챗봇으로 묻고 답 받는" 방식이 빠르게 밀려나고 있다는 건, 업계 전반의 흐름이 어디를 향하는지 꽤 명확하게 보여주는 신호다.

## 배경 — 기존에는 어땠나?

지금까지 기업들이 AI를 도입하는 방식은 대체로 비슷했다. 직원이 챗봇(ChatGPT, Copilot 등)에게 질문을 던지면 답을 받고, 그걸 다시 자기 손으로 코드나 문서에 옮기는 식이다. AI는 "도와주는 도구"였고, 실행은 항상 사람이 직접 했다.

문제는 이 방식이 생각보다 비효율적이라는 점이다. 챗봇은 텍스트를 잘 생성하지만, 실제 업무 환경 — 코드 저장소, 테스트 환경, 배포 파이프라인 — 과는 연결되지 않는다. 개발자가 AI의 답을 받아서 다시 코드에 붙여넣고, 오류가 나면 다시 챗봇에 물어보고, 반복하는 과정은 여전히 사람의 손을 많이 탔다.

GitHub Copilot이나 Cursor 같은 도구들이 이 간극을 좁혀줬지만, 이것들도 기본적으로 "코드 자동완성" 수준이었다. 전체 작업 흐름을 끝까지 스스로 처리하는 도구는 아니었다.

## 핵심 — 무엇이 다른가?

Codex는 다르다. 코드 자동완성이 아니라 **작업 단위의 자율 실행**이 핵심이다.

작동 방식을 단계로 보면:
1. 개발자가 해결해야 할 문제(또는 기능 추가 요청)를 Codex에 전달한다
2. Codex가 코드베이스(기존 코드 전체)를 분석한다
3. 코드를 작성하고, 자체적으로 테스트를 실행한다
4. 오류가 나면 스스로 디버깅해서 수정한다
5. 최종적으로 PR(Pull Request — 코드 변경 제안서, 다른 개발자가 검토하기 전 단계)을 생성해 사람에게 넘긴다

사람이 하는 건 처음 지시와 마지막 검토뿐이다. 중간의 실행 전부를 Codex가 혼자 처리한다.

기존 챗봇 방식과 비교하면:

| 항목 | 챗봇 방식 | Codex 에이전트 방식 |
|------|----------|-------------------|
| 코드 작성 | AI가 제안, 사람이 붙여넣기 | AI가 직접 작성·저장 |
| 테스트 실행 | 사람이 직접 실행 | Codex 자동 실행 |
| 오류 수정 | 다시 챗봇에 질문 | 자체 디버깅 반복 |
| 작업 완료 형태 | 텍스트 답변 | PR 생성까지 완료 |

오픈AI 내부에서 이 방식으로의 전환이 이미 99% 수준까지 완료됐다는 건, 실험이 아니라 실제 운영 환경에서 검증된 결과라는 의미다.

## 시장 영향 — 어디에 쓰이나?

- **개발자 업무 변화**: 코드를 직접 짜는 시간보다 Codex가 만든 결과물을 검토하고 방향을 잡는 데 시간을 쓰게 된다. "코딩하는 개발자"에서 "AI를 지휘하는 개발자"로 역할이 이동한다
- **AI 도구 시장 재편**: 단순 코드 자동완성 중심의 기존 AI 코딩 도구들은 자율 실행 에이전트와 직접 경쟁해야 하는 국면에 접어든다
- **기업 AI 도입 전략 변화**: "챗봇 도입 → 사원 교육"이라는 기존 공식이 흔들린다. 업무 흐름 전체를 에이전트에 넘기는 방식의 도입이 논의 테이블에 올라오게 된다

## 병규의 한 줄

이번에 눈에 띄는 건 수치 자체보다 그 수치가 나온 곳이다. 오픈AI는 AI 챗봇을 세상에 내놓은 회사인데, 그 회사 안에서 챗봇 사용이 사실상 사라졌다. '대화형 AI'라는 패러다임이 자기 창조자에게 먼저 버려진 셈이다.
